# ПИФ Навигатор PRO

Мини-приложение для специалистов управляющих компаний ПИФ, специализированных депозитариев, аудиторов, бухгалтеров и юристов. Статический сайт для GitHub Pages, без сервера и ключей API.

## Что умеет

- Поиск по ключевым словам, номеру документа и пункту: документ → соответствующая статья или пункт → ссылка на источник.
- Профессиональные синонимы: СЧА, ПДУ, SPPI, FVTPL, погашение, оценка, капитал и обязательства.
- Фильтры по источнику, теме, типу ПИФ, статусу и дате оценки сроков.
- Отдельные даты начала применения и исполнения требования; материалы с неизвестной датой показываются отдельно.
- Избранное в браузере, экспорт текущей подборки в CSV и событий в календарь ICS.
- Кликабельная схема документов, визуальные карточки источников, мобильная версия и доступность с клавиатуры.
- Прямые ссылки на Банк России, НАУФОР, IFRS Foundation и справочные редакции закона. Для новых материалов — внешний поиск с ограничением по сайту.

## Поисковые примеры

| Запрос | Результат из указателя |
| --- | --- |
| погашение паёв | 156-ФЗ, статья 23; статья 25 о компенсации |
| оценка облигаций | IFRS 13, пункты 61–67; IFRS 9, пункт 4.1.4 |
| капитал или обязательство | IAS 32, пункты 16A–16B |
| консолидация | IFRS 10, пункты 27–28 и 31–32 |
| цифровые права | сообщение НАУФОР о проекте методологии СЧА |

Результат показывает норму для дальнейшей проверки, а не готовое заключение о применимости. Ссылки на конкретные статьи 156-ФЗ открывают статьи; страницы IFRS не всегда поддерживают переход к пункту — его номер указан в карточке. Полные тексты IFRS могут требовать входа или подписки.

## Публикация на GitHub Pages

1. Загрузите содержимое этой папки в корень репозитория `App-PIF-`, ветка `main`.
2. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Во вкладке **Actions** запустите **Publish PIF Navigator → Run workflow** либо сделайте новый коммит в `main`.
4. После успешного выполнения адрес: `https://zakkaterina1203-arch.github.io/App-PIF-/`.

Публикация через Actions доступна в пределах возможностей вашего тарифа и настроек репозитория. Альтернативно можно выбрать **Deploy from a branch → main → /(root)**: сайт работает без сборки, но ежедневный отчёт мониторинга тогда не обновляется на опубликованном сайте.

Все внутренние пути относительные, поэтому приложение работает в подпапке проекта GitHub Pages. Внешняя загрузка шрифта необязательна: предусмотрен системный шрифт.

## Локальный запуск и проверка

Требуется Node.js 20.11+; рекомендуется Node.js 22. Установка пакетов не нужна.

```sh
npm start
```

Откройте `http://127.0.0.1:4173`. Прямое открытие `index.html` через `file://` может блокировать загрузку JSON браузером.

```sh
npm test
npm run monitor
```

## Что именно входит в базу

`data/catalog.json` — тематический редакционный индекс, проверенный 31.10.2026 по доступным публикациям. Это **не полное собрание всех норм, поправок или полных текстов**. Тексты пояснений написаны для поиска; они не являются дословными выдержками из документов. Все изменения базового 156-ФЗ следует проверять по перечню изменяющих законов и обзору редакций в источнике, а официальные публикации — на правовом портале.

Дата оценки сроков меняет сравнение с известной датой вступления/применения, но **не восстанавливает исторический текст**, не проверяет отмену нормы и не учитывает досрочное применение автоматически. «Применяется» означает только, что указанная в записи дата наступила; применимость к конкретному фонду проверяет специалист. Записи базовых документов имеют статус «Базовый документ / справка», поскольку индекс не удостоверяет каждую редакцию полного текста.

Даты МСФО — сроки IASB, а не подтверждение введения в РФ. Область применения МСФО, внутренних стандартов СРО и требований к СЧА различается. Тип фонда в фильтрах служит тематической меткой, а не правовым заключением. Для проектов НАУФОР статус показан по указанному сообщению; последующее утверждение необходимо проверять.

## Как поддерживать изменения

У каждой записи есть источник, краткое пояснение, тематические метки, указатель пунктов и заметка о сроках. Для дополнения отредактируйте `data/catalog.json`:

1. Найдите официальный опубликованный документ и все изменяющие акты.
2. Добавьте запись с уникальным `id`, полями `code`, `title`, `category`, `publisher`, `kind`, `state`, `published`, `topics`, `funds`, `url`, `summary`, `action`, `dateNote` и массивом `clauses`.
3. В `clauses` укажите точные `ref`, `title`, `text`, `keywords`, `url`. Не придумывайте пункт, если источник содержит только новость.
4. Для принятой нормы используйте `state: "adopted"` и подтверждённую `effective`. Если дата начала применения отличается от вступления в силу, добавьте `application`; статус в выдаче определяется по ней. Для отдельных сроков создавайте отдельные записи. Крайний срок исполнения — `deadline`, не `effective`.
5. Для согласованного проекта без подтверждённого утверждения используйте `state: "project"`, для неизвестного срока — `"review"`, для указателя базового текста — `"reference"`.
6. Заполните условия применения в `dateNote`. После полной редакционной проверки индекса измените `checkedAt`. При частичной проверке не обновляйте эту общую дату.
7. Запустите `npm test` и проверьте несколько содержательных поисковых запросов.

Workflow ежедневно в 05:20 UTC (08:20 МСК) проверяет доступность и изменения нескольких страниц источников, затем публикует сайт. Предыдущее наблюдение хранится в GitHub Actions Cache; после очистки кэша проверка снова будет первым наблюдением. При отсутствии активности GitHub может отключать запланированные запуски; состояние смотрите во вкладке Actions.

Мониторинг **не добавляет нормы автоматически**, не трактует изменения страниц как поправки и не меняет дату редакционной проверки. Динамические элементы страниц могут давать ложные сигналы. Блокировки сайтов и ошибки доступа показываются отдельно в разделе «Источники и охват». Для промышленной полнотекстовой базы и гарантии полноты нужны лицензированные данные и отдельный процесс правовой проверки; GitHub Pages самостоятельно это не обеспечивает.

## Конфиденциальность

Поиск и избранное работают локально. Приложение не содержит аналитики, регистрации или API-ключей. При открытии внешнего поиска запрос передаётся Google; при переходе к источнику — соответствующему сайту. Шрифт загружается с Google Fonts; при необходимости удалите первую строку `styles.css` для работы без него.

Исходные правовые документы и стандарты принадлежат соответствующим правообладателям. В репозитории находятся ссылки, тематические указатели и редакционные пояснения, без копий полных текстов стандартов.
